# Kelvin — Strategic Advisor (Telegram-first)

Цель: личный советник основателя iumrah, аналитик рынка и мост к клиентам. Это накопительный патч к ранее выпущенному Kelvin Business Sync / Telegram Thinking. Оригинальное дерево OpenJarvis не меняется, GitHub workflows не меняются. Не использовать параллельный gateway: должен быть только один poller для каждого Telegram-бота.

## Установка на уже работающем Mac
1. Загрузить `jarvis-update-kelvin-strategic-advisor.zip` в корень kepler-maneger-. Проверить, что распаковка успешна и ZIP удалён из текущего дерева.
2. На Mac обычным пользователем: `cd ~/Kelvin && git pull --ff-only && bash founder_jarvis/macos/install.sh`.
3. В приватном Telegram: `/health`, затем обычный вопрос, `/briefing`, голосовое 5–10 секунд, `/voice Привет`.
4. Если Business Sync уже связан, ключ сохраняется. Иначе в обновлённом iumrah Business → Kelvin → Подключить Mac создать ключ; на Mac `bash founder_jarvis/macos/link-iumrah.sh`. При отсутствии ключа бот работает локально, данные iumrah ему не доступны. Не передавать токены в чат и не публиковать в Git.
5. Оставлять Mac подключённым к питанию, крышка открыта, пользователь вошёл в систему. `sudo pmset -c sleep 0 displaysleep 5` предотвращает idle sleep на питании, не гарантирует работу с закрытой крышкой/при выключении. LaunchAgent сохраняется.

## Что именно использовано из оригинального OpenJarvis
- OrchestratorAgent: штатный multi-turn loop с выбором инструмента, наблюдениями и финальным ответом. Тонкий Claude CLI transport использует ранее авторизованный CLI без включения его собственных tools/MCP.
- WebSearchTool: публичные темы market/competitors/marketing/platforms; бесплатный DuckDuckGo, доступность и качество выдачи не гарантируются. Запросы фиксированные, приватные данные не подставляются. Отчёты и вопросы о рынке принудительно получают поисковые результаты, ссылки из результатов добавляются отдельно. Это поиск по ограниченному набору тем, не полноценный Deep Research/мониторинг всех конкурентов.
- TaskScheduler/SchedulerStore: штатный периодический планировщик проверяет отчётные слоты 08:00, 12:00, 21:00 Asia/Tashkent. Детерминированные ID, локальный журнал отправки, при позднем старте только последний доступный слот. Если backend недоступен, повтор постановки в очередь; ответ, завершившийся ошибкой модели, нужно повторить вручную `/briefing`. Отчёты сохраняются в общей истории при наличии связи.
- Существующий Telegram/голос, SQLite и D1-история остаются транспортом и единой памятью, без дублирования в дополнительный upstream memory store. Явное «запомни ...», /remember, /memory, /forget; краткий контекст последних сообщений. Автоматическое извлечение долговременных фактов OpenJarvis не подключено. Старые локальные диалоги не мигрируются.
- Операции разработки, терминал, файловая запись, деплой, Meta и платежи не выдаются агенту. Старые команды скрыты и старые задания операций блокируются. Не подключены native Operative/Monitor Operative/Deep Research/Morning Digest, браузер, произвольные MCP и живые звонки — не выдавать наличие исходников за активацию.

## Клиентский Telegram: один отдельный бот для клиентов
Не использовать приватный KelvinManagerBot для клиентов. Если действующий iumrah Care имеет webhook или другого poller, не отключать и не перехватывать его. Для первого испытания создать тестового клиентского бота в BotFather.
`cd ~/Kelvin && bash founder_jarvis/macos/connect.sh business telegram`
Токен ввести скрыто. Команда проверяет getMe и отсутствие webhook, сохраняет локально и включает безопасные автоответы. После команды `/biz status` в приватном боте. Если клиентский токен был настроен раньше, `/biz auto-on`.
Клиент может отправить «Сколько стоит умра?»; Kelvin спросит даты, город и число человек. Не называет цену без проверенной информации, не бронирует, не принимает деньги. Неизвестные вопросы эскалируются. Автоответы текстовые (русский/узбекский с ограниченной эвристикой языка), голос клиента пока не обрабатывается.
В приватном Telegram: уведомление с вопросом, фактом отправки и ответом; кнопки Взять общение / Продолжай сам / Переписка. После перехвата новые входящие только уведомляют; `/biz reply ID текст` отправляет ручной ответ и включает перехват, в том числе после предыдущего автоответа. `/biz auto-off` отключает автоответы глобально. `/biz pending` показывает ожидающие. `/biz resume ID` возобновляет новые автоответы.
Проверенная база FAQ находится в `~/Library/Application Support/Kelvin/business-faq.json`. Создать пустой шаблон `bash founder_jarvis/macos/connect.sh business faq`. Формат: `[{"questions":["пример вопроса"],"answer":"утверждённый владельцем ответ"}]`. По желанию `bash founder_jarvis/macos/connect.sh business local` подключает уже установленную Qwen для выбора одного утверждённого ответа по смыслу, не для генерации цен. Если модели нет, используются безопасные шаблоны. В этой версии платный клиентский API не используется. Личный Claude работает согласно условиям подписки; не обещается безлимитность или бесплатность API.
Уведомления хранятся до подтверждения доставки. При неоднозначном результате отправки клиенту нет автоматического повтора; требуется ручная проверка. При сбое между отправкой уведомления и записью подтверждения возможен повтор уведомления, не повтор клиентского ответа.

## Приёмка на Mac и реальные тесты
- `/health` показывает версию, наличие CLI, native Python, планировщик и реальную связь backend. Это не доказательство работы модели.
- Обычный вопрос, затем «Проверь конкурентов» и `/briefing`: проверить ответ, ссылки и отсутствие выдуманных данных.
- «Напомни через 2 минуты проверить заявки»: проверить доставку; `/tasks` локальные поручения.
- «Запомни тестовое решение ...» в Telegram, затем вопрос в Business и обратно. Проверить с реальными аккаунтами.
- `/diagnose` и новое голосовое, затем заблокировать Mac и повторить. Проверить после перезапуска/входа.
- От отдельного Telegram-аккаунта написать клиентскому тестовому боту, проверить автоответ, уведомление, перехват, отсутствие ответа после перехвата, ручной ответ и возобновление. Не тестировать на реальных клиентах до подтверждения.
- Проверить все 3 отчётных слота и 72 часа работы на Mac. Принимаются только реальные результаты.

Локальные тесты запускаются в install.sh: 기존 46 регрессионных + 7 новых runtime + 5 native tests. Модель, веб-поиск и Telegram API в тестах подменены; оригинальный Orchestrator и TaskScheduler выполняются непосредственно. Mac/Claude/Cloudflare/Telegram и поиск по сети не проверены в среде сборки.
