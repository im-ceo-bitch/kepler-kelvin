# JARVIS — запуск приватного Telegram-агента

Независимая адаптация OpenJarvis (Apache 2.0). Оригинальный README, LICENSE, ядро, тесты, frontend и desktop сохранены. Исходный архив имел оборванный центральный каталог: 2501 локальная запись восстановлена с проверкой CRC и размеров; полного оригинального центрального каталога нет. Оригинальные GitHub Actions перенесены в `upstream-workflows/`, чтобы новая копия не запускала публикацию PyPI, upstream-релизы, сторонние CI и ботов автоматически. Для возвращения upstream CI восстановите выбранный workflow после проверки. Ваш распаковщик не включён и не изменён.

## 1. GitHub

Создайте новый репозиторий (предпочтительно `jarvis`). ZIP содержит файлы прямо в корне, без обёртки `OpenJarvis-main/`. Используйте существующий распаковщик. В Settings → Pages → Build and deployment выберите GitHub Actions. В Actions вручную запустите `JARVIS portfolio Pages`. Если распаковщик не переносит `.github/workflows`, добавьте только `founder-pages.yml` вручную из ZIP. Pages публикует исключительно `portfolio-site`, не Python backend. Публичный репозиторий/портфолио не должны содержать `.env`, базы или рабочие файлы.

## 2. Локальный запуск (Mac Intel / Linux)

Клонируйте новый репозиторий на Mac. Установите uv, Ollama, ffmpeg. На Mac проверьте русский системный голос `say -v '?'`; при необходимости скачайте голос в настройках macOS или установите `JARVIS_MAC_VOICE` на доступный русский голос. Linux: `espeak-ng` + `ffmpeg`. Для локального теста запустите Ollama и загрузите `ollama pull qwen2.5:3b`. Маленькая модель может ошибаться с tool calling; при необходимости выберите более мощную модель на удалённом сервере. Проверьте совместимость версии Ollama с macOS. Для облачного движка см. оригинальные настройки OpenJarvis и используйте поддерживаемую API-аутентификацию; подписка Claude не гарантирует доступ по API.

```bash
cp .env.example .env
chmod 600 .env
# Заполнить .env в локальном редакторе.
bash founder_jarvis/start.sh
```

Создайте бота через @BotFather, сохраните токен только локально. `JARVIS_OWNER_ID` — ваш числовой Telegram user ID (не username и не номер телефона). Его можно получить через официальный Bot API getUpdates после отправки боту /start; не отправляйте URL с токеном третьим лицам. До заполнения обоих значений runtime не запускается. Не запускайте оригинальный Telegram gateway и этот бот одновременно с одним токеном.

По умолчанию данные (`jobs.sqlite3`, настройки, audit) находятся в `~/.founder-jarvis`, рабочие файлы — в `~/.founder-jarvis/workspace`. Можно указать `JARVIS_WORKSPACE` с отдельным локальным тестовым клоном репозитория без секретов. Не указывайте весь домашний каталог, production checkout или каталог с `.env`. Не используйте привилегированного пользователя. OpenJarvis file policy — не полноценный OS sandbox. При использовании облачной модели текст/контекст может передаваться провайдеру, а голос и ответы передаются через Telegram.

## 3. Реальные проверки

- /start — разрешён только приватный чат владельца; чужие пользователи игнорируются.
- Текст: «Посчитай 347 * 91 через calculator» — проверить ответ и отчёт инструментов.
- Голосовое: тот же запрос. Первый запуск Whisper требует загрузки модели. Ответ текстом и OGG/Opus через системный TTS.
- «Найди в интернете документацию OpenJarvis» — web_search при наличии сети.
- /edit Создай test.txt с текстом JARVIS ONLINE — задача pending, затем /approve ID; проверить реальный файл в workspace. Обычный текст/голос не включает инструменты записи.
- /gitstatus — реальный git status в рабочей папке. /tasks, /result ID, /cancel ID (только queued/pending). Блокировка телефона не останавливает локальный worker. Сон/выключение Mac остановит выполнение; после перезапуска running помечается interrupted, queued сохраняются. Не повторяйте прерванное изменение без проверки файлов.
- Память: последние шесть завершённых диалогов подставляются в контекст; полный журнал задач хранится локально. Это не семантическая долговременная память.

Тесты нового слоя без токена: `python -m unittest founder_jarvis.test_runtime -v`. Python 3.11–3.13. Стартовый скрипт устанавливает upstream и голосовые зависимости через uv; впервые потребуется интернет. Реальный Telegram/Ollama/Whisper/TTS, upstream dependencies и GitHub Actions не проверены в окружении сборки. Не считать портфолио подтверждением deployment. Обычный режим имеет ограниченный набор инструментов. Shell, браузер GUI, Claude SDK, GitHub PR, Cloudflare, Instagram, файлы/фото через Telegram, расписание, непрерывная голосовая сессия — сохранены где имеются в upstream, но не подключены к новому приватному режиму. Для этих интеграций нужны отдельные тесты и безопасные разрешения. Для 24/7 потребуется постоянно работающий Mac или VPS.
