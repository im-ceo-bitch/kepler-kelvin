# Kelvin — Blocks 02–03 cumulative release
Дата: 27.11.2026. Статус: реализация в доступных снимках; локальные регрессии выполнены. Production acceptance BLOCKED (нет доступа к целевому Mac, живым API, текущим HEAD и iOS SDK). Блоки 04–07 не начаты. Никаких изменений live business данных, аккаунтов и GitHub Actions.

## Архитектура и изменения блока 02
Сохранены SystemBuilder → JarvisSystem → Orchestrator, штатный ToolExecutor, Security и аудит. Адаптер модели позволяет выбрать Claude CLI (в рамках разрешенного личного использования) либо явно Ollama. Нет неявного платного fallback. Типизированная память: personal/business/episodic/decision/task/research, источники, версия, статус кандидата, исправление/удаление. При связке с iumrah канонические записи в существующем D1, локальная проекция использует SQLite FTS5/BM25. Старые сообщения не должны автоматически возвращать удалённый факт. Точное извлечение до трёх явно выраженных фактов-кандидатов без дополнительной генерации. Это не полноценное автоматическое семантическое извлечение; upstream Rust FactStore/MemoryService не подключены. Клиентский контекст не смешивается с личным. Старые диалоги не импортируются автоматически. См. BLOCK-02-IMPLEMENTATION.md и evidence/block02-* для предыдущих проверок.

## ADR-09: автономность и уведомления разделены
Штатный OpenJarvis TaskScheduler/SchedulerStore и EventBus запускают interval tick; только один callback активен. SQLite ledger `autonomy.sqlite3` хранит задания, attempts, окна, источник, бюджет, результаты, факт попытки доставки и аудит. Новый `autonomy.py` — предметная политика, не второй LLM-агент. `research_evidence.py` — контракт наблюдений, цитат и рекомендаций. `advisor.py`, `native_advisor.py`, `intelligence_core.py` — ограниченный запуск исходного Orchestrator и WebSearchTool через ToolExecutor, отдельный subprocess с таймаутом 180 s, один вызов генерации на исследование; при невалидном отчёте нет рассылки. `runtime.py`, `shared_business.py` — один runtime, отказ от старого автоматического report loop даже при legacy env flag, стандартное typing, архив предыдущих source=briefing без генерации; сохранены ручные напоминания. Приоритет владельца перед запуском исследования; уже начатое может задержать запрос до предельного таймаута (target Mac benchmark NOT RUN). Фоновые явные API-ключи не используются без KELVIN_ALLOW_PAID_BACKGROUND=1; тарификация/лимиты авторизованного CLI отдельно не наблюдаемы. Не обещать денежный потолок.

Native DeepResearch требует совместимой structured tool-call семантики и дополнительные зависимости; не активирован. Operative/MonitorOperative/Proactive/MorningDigest не запущены параллельно; их задачи выполняет ограниченная политика на оригинальном scheduler/executor. Это сознательная замена профилей, не утверждение, что все агенты OpenJarvis интегрированы. Native browser и page fetch отложены до проверки доступа/безопасности.

## Расписание, Asia/Tashkent
08–11: одно короткое текстовое утреннее сообщение, <=900 символов, с доступной метрикой и максимум одной рекомендацией из свежего исследования; без обязательного голосового дубля. 12–16 и 16–20: два исследовательских окна, только архив. 21–23: вечерний обзор, только архив. Пропущенные окна не догоняются, по одному durable ID на день/слот. Каждые 30 мин при подключении backend — фиксированный read-only snapshot. Важное: подтверждённый рост непрочитанных обращений (>=5, прирост >=3, повторное наблюдение), максимум 1/день, quiet hours 22–08. Критическое предупреждение: ранее доступный агрегат бронирований стал недоступен в двух последовательных проверках; это не доказательство полного сбоя, максимум 1/день, quiet hours не блокируют. Неизвестные данные не равны нулю. Автоматический Telegram максимум 2 обычных/важных сообщения в день + критическое исключение. Отдельные явные напоминания и клиентские сообщения не включены в этот потолок. `/autonomy off` сохраняет паузу, гасит ожидающие уведомления; не может отозвать уже отправленное. `/autonomy on`, `/autonomy status`, `/insights`, `/briefing` доступны.

2 attempts/job, 15 min backoff, до 4 research attempts/day persisted, до 1 model generation/research attempt, 5 attempts архивной доставки на id. При неопределённом подтверждении Telegram попытка отмечается uncertain и автоматически не повторяется (может быть пропуск уведомления; не exactly once). Idle scheduler не вызывает модель. Research reports и уведомления раздельны. При недоступности Mac не исполняются, работа возобновляется в текущем допустимом окне. Полный контроль клиентских событий — блок 05.

## Исследования и доказательства
9 тем: рынок умры, конкуренты, маркетинг, travel platforms, спрос, хадж/умра, поведение клиентов, соцсети, риски. По одному общему направлению и одному публичному предложению в день; ограниченный адаптивный выбор следующей темы из whitelist каждые три дня. Начальный watchlist из пяти публичных предложений (не подтверждение лицензии, цен, наличия, прямой конкурентности):
- Centrum Holidays / Centrum Air: https://umra.centrum-air.com/?lang=ru
- UMRABOR: https://umrabor.uz/ru
- Umra Platformasi: https://umraplatforma.uz/ru/umra
- Safarga: https://safarga.com/en
- Hikmat Umra Travel: https://hikmatumra.uz/
Публичные поисковые запросы фиксированы, не включают личные данные. Наблюдение = URL, title, snippet, observed_at (время получения, не публикации), hash по теме/URL/выдержке. Первое наблюдение watchlist — baseline без генерации. Повтор выдержки не вызывает модель. Разница snippets не означает изменение предложения; отмечается именно как изменение доступной поисковой выдержки. Модель возвращает структурированные наблюдения с точной цитатой из доступного источника; неизвестные URL и выдуманные цитаты отклоняются. Влияние, рекомендация, риск, измерение — гипотезы. Полные страницы, даты публикации, независимое подтверждение и реальное качество исследования NOT RUN. Не выдавать 30 fixture assertions за 30 проверенных рыночных фактов. Поисковые данные не становятся подтверждённой памятью владельца автоматически.

## Миграция / установка / rollback
Один накопительный архив на каждый репозиторий. На восстановленных доступных snapshots `kepler-maneger--main.zip` и `lattice-mobile-main 3.zip` с предыдущими патчами; актуальные HEAD неизвестны. Сверить изменённые файлы с текущим HEAD, сохранить commit SHA/backup, при конфликте не применять вслепую. В Business архив включены исходная интеграция, блок 02 и hotfix компиляции; Kelvin включает strategic advisor, документацию 01, 02 и 03. Не применять старые архивы поверх cumulative release. Распаковщики/Actions не меняются. Сначала Business: распаковать, проверить backend staging/backup D1, применить существующий deploy и TestFlight. Затем Kelvin: распаковать и проверить repo, на Mac `cd ~/Kelvin && git pull --ff-only && bash founder_jarvis/macos/install.sh`. Backup локальных SQLite при preflight (jobs и autonomy); секреты не экспортируются. Если нет pairing, использовать существующую привязку из Business и `bash founder_jarvis/macos/link-iumrah.sh`. При ошибке остановить autonomy `/autonomy off`, сохранить журналы, откатить код на проверенный commit с учётом обратной совместимости D1; не удалять БД и не включать старые отправки без проверки. Изолированное восстановление backup только после остановки процесса. Не запускать два Telegram poller. Без VPS; Mac должен оставаться включенным и подключённым к сети; Claude удалённый, условия личного CLI обязательны. Новых обязательных платных сервисов нет.
