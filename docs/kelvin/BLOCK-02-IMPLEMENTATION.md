## ADR-09: единый агентный цикл
`Telegram / Business → существующая очередь D1 → shared_business → native_advisor → SystemBuilder.engine_instance → JarvisSystem.ask → ScopedOrchestrator → ToolExecutor → модель`. Использованы оригинальные SystemBuilder, JarvisSystem, OrchestratorAgent, SystemPromptBuilder, EventBus, security runtime (capability policy, guardrails, rate limiter, audit), FactExtractor и существующий WebSearchTool. Код `src/openjarvis/` не изменён. ScopedBuilder ограничивает набор инструментов и отключает несовместимую автоматическую инициализацию memory backend. ScopedOrchestrator использует штатный structured protocol: Claude CLI не выдаёт native tool calls для этого контракта. Максимум 4 итерации, целевой max_tokens=3000 (CLI не гарантирует enforcement этого параметра), последовательное исполнение. Только публичный market_search с допустимой темой, без произвольного URL, SQL, команд, изменения бизнеса, переписки или деплоя. Журнал метаданных вызовов локальный. Смена `KELVIN_PROVIDER=claude|ollama` и `KELVIN_LOCAL_MODEL` в runtime.env не требует менять Core; автоматического переключения на платный провайдер нет. Установка пока сохраняет прежний prerequisite Claude CLI. SOUL.md/USER.md опциональны, MEMORY.md не подмешивается. Редактируемые вручную профили и backups не являются частью операции forget. Длительные сессии восстанавливаются через общий контекст, а не через непрерывно работающий процесс модели.

## ADR-10: долговременные записи
D1 — единственный авторитетный источник типизированной памяти для связанного владельца. `kelvin_memory_records` хранит id, scope, kind, content, source, trust, version, timestamps; изменения/удаление CAS, tombstones, metadata audit. Шесть типов: personal/business/episodic/decision/task/research. Customer закрыт до блока 5; автоматическая связка с жизненным циклом задач/исследований не сделана. Каноническая память общая; индекс FTS5/BM25 строится в памяти процесса из текущего снимка, не сохраняет удалённые данные. Причина: штатные SQLite/BM25 backend этой версии OpenJarvis требуют Rust extension, доступность на Intel Mac не доказана; MemoryService/FactStore не активированы (нужны durable scoped ids/versions). Нативный FactExtractor по `/extract` возвращает кандидатов, только дословные цитаты владельца, для подтверждения. Простой детерминированный capture некоторых явных заявлений не тратит вызов модели. Неподтверждённые кандидаты не подаются в модель. Не обещаем полное автоматическое извлечение из любой беседы или embedding semantic search.

Контекст — свежий снимок разрешённых записей, до 12 результатов / 14k символов, плюс последние 20 сообщений. Старые диалоги целиком не становятся памятью автоматически. До 1000 строк на владельца (включая tombstones), до 2000 UTF-8 bytes на запись; перед массовым импортом проверить лимит. Пагинация списка, версия для исправления, удаление из активного контекста, сброс подачи более старой сырой истории при исправлении/удалении; исторический UI и backups сохраняются. Полное уничтожение данных не реализовано. Текст ранее вручную занесённый в SOUL/USER или повторно сообщённый пользователем может быть снова известен. Передача приватных данных модели ограничивается guardrails/проверкой секретов; это не доказательство отсутствия всех возможных утечек.

## Использование
`/remember decision: текст` или `Запомни ...`, `/memory`, `/memory candidates`, `/confirm_memory ID версия`, `/correct ID версия decision: новый текст`, `/forget ID версия`, `/extract business: текст`. Обычный запрос на RU/UZ использует поиск. В iOS — просмотр, подтверждение, редактирование, удаление записей. После привязки все команды используют общую очередь; если новый API недоступен, запрос не обрабатывается через тихую альтернативную историю. Без привязки остаётся прежний локальный режим совместимости; полноценная общая память требует связанного backend.

## Миграция и безопасная установка
1. Сверить HEAD обоих репозиториев с исходным базисом; проверить отсутствие конфликтов. Сохранить текущие версии, сделать штатный backup D1 и локального runtime. Не менять production до staging и проверки. Backend ZIP сначала: существующий pipeline деплоя (не добавлен новый workflow); в staging проверить records API и iOS сборку. Новые таблицы создаются в существующем Kelvin namespace; бизнес-таблицы не изменяются. Legacy shared notes переносятся идемпотентно при обращении к памяти.
2. Kelvin ZIP после доступности нового backend. На Mac `cd ~/Kelvin && git pull --ff-only && bash founder_jarvis/macos/install.sh`. Установщик запускает проверки, делает проверенный локальный SQLite backup в `~/Library/Application Support/Kelvin/backups`, проверяет typed API при наличии привязки, затем регистрирует сервис. Ключи и конфигурацию заново не вводить при существующей привязке. Если её нет — существующий link-iumrah.sh.
3. Локальные старые заметки: dry-run `"$HOME/Library/Application Support/Kelvin/telegram-venv/bin/python" -m founder_jarvis.memory_migrate` из корня репозитория. Только после проверки `--apply`. Опция `--include-history` добавляет старые завершённые пользовательские запросы (не ответы); использовать только осознанно и при достаточном лимите. Идентификаторы стабильны, повторный импорт не восстанавливает tombstones. Backup может содержать личные данные, хранить приватно.
4. Проверка на тестовых данных: сохранить новую тестовую цель в Telegram, запросить из Business, исправить в Business, проверить Telegram, удалить, проверить отсутствие в активной памяти. Не использовать реальные клиентские данные. Проверить /health, реальный ответ Claude и локальный Ollama при наличии. При отказе остановить новый runtime, вернуться к прежнему коммиту обоих репозиториев и существующему workflow. Новые таблицы не удалять автоматически; старый runtime не видит новые типизированные записи, сохранить backup и отдельно проверить совместимость перед откатом. Не восстанавливать всю D1 поверх живых бронирований. План rollback не исполнен на staging.

Фактические тесты: 72/72 Kelvin Python; 228/228 iumrah backend; 273 passed, 44 skipped выборочные оригинальные OpenJarvis tests (включая память/Orchestrator/security/prompt). Skipped не считаются пройденными. Синтаксис двух Swift-файлов и install.sh проверен. Старые ResourceWarning о незакрытых SQLite connections сохраняются в тестовом журнале, это не новый зелёный production gate. Использовались тестовые модели и SQLite-реализация D1; live API, нагрузка на Intel 8GB, качество RU/UZ и iOS build не измерялись. Нет основания заявлять production readiness.
