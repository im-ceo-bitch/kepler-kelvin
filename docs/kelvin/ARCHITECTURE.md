# Kelvin — целевая архитектура (ADR, блок 1)
Статус: проектное решение, не реализация. Связанные документы: BLOCK-01-AUDIT.md, ROADMAP.md, evidence/VALIDATION.md.

## ADR-001. OpenJarvis — ядро, а не папка рядом с runtime
Переиспользовать `SystemBuilder`, `JarvisSystem`, `OrchestratorAgent`, `AgentContext`, registry, `EventBus`, `ToolSpec`, `ToolResult`, `TaskScheduler`, `SchedulerStore`, память и security. Сначала spike на реконструированном baseline: собрать upstream с custom `engine_instance`, реальными инструментами-заглушками только в тестах и upstream security. Если upstream config не даёт нужного wiring, тонкий adapter с явно перечисленными gaps, не новый агентный цикл. Модель через стандартный InferenceEngine, capability descriptor (text, structured tools, native tool_calls, stream, cancellation, health, usage). `DeepResearchAgent` нельзя просто переключить с текущего ClaudeTransport: он использует tool_calls, которых adapter не возвращает. Сначала проверить native calls или использовать штатный structured Orchestrator для research с approved toolset. Operative/Monitor/Proactive подключать отдельными ограниченными run-профилями после бюджета и тестов. Не активировать все модули одновременно; программирование, shell, произвольный file write, git push, payments и self-modification deny. Архитектурная схема:

```
Telegram owner ─┐                 Cloudflare (существующий Worker/D1)
Business iOS ───┼─> auth/ingress -> canonical owner events + durable delivery outbox
                │                       ^ HTTPS pull/ack (Mac исходящие соединения)
Care Telegram -> existing Care webhook -> customer events / authoritative thread state
                                        |
MAC: supervisor/LaunchAgent -> OpenJarvis system + security + scheduler + event handlers
                    |            |                 |                |
                    |            |                 |                +-> notification gate
                    |            |                 +-> research / digest / monitor
                    |            +-> scoped tools (read-only iumrah, public web, memory)
                    +-> provider adapters (approved local/cloud) + speech workers
                      owner memory retrieval/projection + customer memory isolation
```
Существующий Telegram runtime сохранять на время миграции, но строго один poller на bot token; на owner Telegram можно сначала оставить PTB, пока штатный channel не пройдёт voice/auth tests. Care production использует текущий webhook, а не второй getUpdates. При переносе ingress на существующий Worker необходимо переключать токен атомарно с rollback, не одновременно webhook и poller.

## ADR-002. Границы полномочий
Owner identity: привязка private Telegram ID к конкретному авторизованному superadmin в iumrah, не username. Pairing: short-lived one-time secret для provisioning, отдельный device token с hash/expiry/revocation, rotate с fencing. Не расширять права существующего token до D1 Admin. Customer identity: channel/account/thread ID; разные customers не делят session. Входящие client/public/connector данные — недоверенные; prompts не могут выдавать permissions. Tools fail closed: owner read business, public research, schedule within policy, memory CRUD own scope; customer только approved FAQ/context и authorized send/handoff via Care. Ни платежей, ни ценовых изменений, ни бронирований, ни deploy, ни shell в этих профилях. Client model не получает owner memory, business secrets или произвольный URL. Личные и клиентские данные не передаются в public search. Облако получает только нужные минимизированные поля, без паспортов/телефонов/секретов; пользовательская авторизация/политика хранения отдельно проверяются. Ссылки/HTML содержат untrusted content, SSRF deny private/local/cloud metadata и redirects. Логи с correlation id, safe metadata, без raw tokens/PII; trace payload по умолчанию не записывать.

## ADR-003. Единая память — авторитет, а не копии
Cloudflare D1 — существующая авторитетная owner history/events и статус доставки; расширить её typed memory API (миграции отдельным блоком, не произвольный SQL). Local OpenJarvis FTS5 — поисковая проекция/кэш тех же owner records, перестраивается из canonical cursor, не независимый источник фактов. Если OpenJarvis memory backend хранит собственные embeddings/indices, это производная, а не вторая истина. Если связка недоступна, локальные записи помечаются unsynced и не сливаются бесконтрольно; durable outbox/UUID и reconcile. Один логический owner profile, distinct customer profile per thread. Не мигрировать старую историю автоматически без явной команды владельца, dry-run и backup.

Логические схемы (проект, имена не закреплены миграциями):
- `memory_record(id,scope,kind,claim,source_ref,source_time,created_at,valid_from,valid_to,trust,verification_state,version,supersedes,expires_at,deleted_at)`; kinds personal/business/episodic/decision/task/research/customer. Факт, гипотеза, рекомендация и approved decision — разные статусы. Исходные business facts читаются из backend при необходимости, не дублировать целую базу.
- `decision`: рекомендация + owner verdict/why, KPI, due review, outcome/unknown. Без owner approval не записывать «решено».
- `task`: stable UUID, priority, state queued/running/waiting/failed/cancelled/done, deadline, attempt, lease/fence, parent, idempotency key, result_ref, next_retry.
- `evidence`: URL, publisher, published/fetched_at, excerpt, hash, verified scope, claim_refs, expiry. Хранить только допустимый объём, не зеркалировать сайты.
- `outbox`: event_id, channel, scope, severity, content_ref, state pending/sending/acked/uncertain, dedup_key, attempts, next_try, external_id. Клиентский authoritative delivery использует текущий Care.

Использовать FactExtractor/MemoryService с event-bus; extraction best effort, для критических decisions — durable source event и explicit confirmation. Не хранить LLM догадки как факты. Retrieval: exact ID, kind and scope filters, freshness, FTS5/BM25, recency/relevance. Автокоррекция с versioning, owner correction wins. SOUL.md — правила личности, USER.md — явные стабильные prefs, MEMORY.md — ограниченная выжимка, не база. Управление: просмотр, редактирование, удаление; tombstone очищает индекс/кэши и исключает re-extraction; объяснить отдельно историю и backups/retention. Политика retention согласуется до production.

## ADR-004. Автономность без спама
Один scheduler с явно заданным timezone Asia/Tashkent и отдельным durable task runner. Native TaskScheduler отвечает за due, не за прямые отправки. Event-driven; без постоянного вызова LLM, no duplicate jobs. Research по расписанию, пользовательские задачи с приоритетом, background preemption/cancel. Restart: повтор безопасных read jobs до 3 попыток с exponential backoff+jitter, uncertain external send не повторять вслепую. Раздельный admission/dispatch/reconcile, lease renewal, generation timeout. Ограничение на количество вызовов моделей и CPU, token count или unknown usage. Предлагаемые стартовые лимиты (не замеренные и не тарифы): один inference process, один тяжёлый speech task, до 4 model turns для обычного диалога, до 8 для research, до 20 автоматических model calls/сутки (owner interactive separate bounded pool), до 5 fetch на topic/цикл; лимиты конфигурируемы, при исчерпании уведомление максимум раз в день и сохранение task. Не запускать оплачиваемый provider без согласия. Native rate limiter/loop guard + отдельный persisted daily budget.

Notification policy вне модели: обычные находки -> хранилище и утренний digest; важные -> только если подтверждённое изменение/действие владельца, dedup fingerprint, cooldown 6 ч; критические -> немедленно по объективному правилу (например длительно недоступен ключевой сервис или сломан клиентский канал), rate cap и resolution notice по запросу. Quiet hours 21:00–08:00, только заранее согласованные critical exceptions. По умолчанию 08:00 одно сообщение ≤900 символов, максимум 3 наблюдения + 1 действие + 1 вопрос если нужен. 12:00 research без отправки. 21:00 review вычисляется, хранится в Business; отправлять ≤600 символов только если есть новый важный unresolved result или владелец включил вечерний отчёт. Это согласование требования утреннего/вечернего обзора с явным требованием не спамить; вечерний обзор существует даже если отправка подавлена. Не дублировать text+voice: voice по запросу/выбранной настройке. Максимум 2 несвязанных с клиентами автоматических обычных сообщений в сутки, важные отдельным лимитом, настраивается. Startup/reconnect/test failures — локальный log, не чат. Не восстанавливать пропущенные старые доклады пачкой: не более одного свежего catch-up, устаревшие только архив. Уведомления клиентов — отдельный поток, каждое содержательное подтверждённое сообщение Kelvin клиенту требует owner notice, без дублирующих queue statuses; urgent customer signals не скрывать. Владелец может mute/digest (только осознанно изменить). Telegram status `sendChatAction(typing)` при actual work, no forced draft/sticker.

## ADR-005. Бизнес/исследования
Оригинальный `WebSearchTool` + vetted URL retrieval, public allowlist, read-only Browser optional после benchmark. Никаких private account scraping или попыток обхода авторизации. Реестр конкурентов (название, официальный URL, market, наблюдаемые услуги, last_checked), изменения только по diff подтверждённых наблюдений. В каждом research item: событие, дата, источники, impact, opportunity/risk, действие, KPI, confidence. Не путать найденный сниппет и доказанную цифру. Цены сравнивать только на сопоставимых датах/составе услуг, mark unknown. Business tools — узкие `get_metrics`, `get_booking_summary`, `get_catalog`, `get_support_topics`, без записи и передачи лишних PII. Метрики: период, числитель, знаменатель, единица, источник, as_of, coverage. Не смешивать overlap legacy chat и Care. План на день учитывает цели, предыдущие решения, свежие сигналы; задаёт вопрос если нет данных, может не согласиться с владельцем и объяснить почему. Никаких «проверил», если tool failure.

## ADR-006. Клиентская коммуникация
Переиспользовать `Backend/IumrahBackend/core/telegram/care.js` (существующие `telegram_care_threads`, `telegram_care_messages`, `mode='auto'|'human'`, staff send, дедупликация и delivery states). На стенде текущий `business.Inbox` допустим, но не production authority. Canonical event from Care -> Kelvin customer policy -> validated answer -> Care send via same thread fence -> confirmed delivery -> outbox owner notice. Если отправка неизвестна, только manual reconciliation. После take thread generation epoch повышается, queued auto tasks invalidate, recheck fence перед send; in-flight send нельзя отменить задним числом, статус pending takeover/uncertain отображать. Manual reply включит human mode до отправки. Resume явный, только новые входящие. Клиентские вопросы contextual slots, verified FAQ/backend, отсутствие цены -> уточнить, не обещать. Локальная модель только для scoped intent/retrieval/draft с валидацией, шаблоны допустимы как fallback, не как вся система. Не делать клиентскую модель на чужой подписке Claude; если локальная модель не проходит тесты, ограниченный режим или согласованный API, не выпускать плохую автоматизацию. Meta adapters future: webhook signature, official permissions, policy windows, comment/direct semantics, token rotation, no production without test. Telegram сейчас, Meta off.

## ADR-007. Голос и интерфейсы
Существующий SwiftUI UI и KelvinVoiceOrb сохраняются, не переоформлять приложение в блоке 2–5. Upstream speech discovery + Faster Whisper CPU int8, TTS выбран после RU/UZ прослушивания. Не утверждать наличие поддерживаемого узбекского голоса. Вариант A локальный STT/TTS, вариант B доступные native iOS on-device RU/UZ, вариант C opt-in коммерческий provider после стоимости и privacy review. Live session = audio chunks + sequence + cancel + transcript revisions + response chunks, bounded buffer, VAD, barge-in останавливает output и устаревший generation; shared owner session. Модель/транспорт должны поддерживать истинное streaming; текущий `ClaudeTransport.stream` не является streaming. Для realtime транспорт выбирать после теста через existing Cloudflare auth (WebSocket/relay или HTTPS chunking); отсутствие публичного порта Mac, no secrets в app. Call/VoIP как future design, не Telegram Bot API feature. UI states queued/working/researching/speaking/error/offline из событий; listening/speaking из реального аудио; фирменная сфера в приложении только, Telegram стандартный typing. Общее history и задачи по ID, iOS не содержит token модели.

## ADR-008. Локальная эксплуатация
Intel Mac 8GB: не предполагать GPU acceleration Ollama, не запускать все engines; foreground responsive + lightweight scheduler, модели on demand, idle unload. Текущие launchd/caffeinate сохранить; login session, AC/lid open, no availability during sleep/shutdown. Существующий Cloudflare Worker может держать auth/queue/read-only metadata, не heavy inference; quotas проверить, никаких обязательных VPS. Secrets вне Git (Keychain или 0600 config, 0700 dir); keep tokens out of argv/logs. Backup SQLite online backup + versioned D1 export/minimal scope, encrypted storage, restore drill. Log rotation, size limits, dependency lock, capability probe, graceful shutdown, boot recovery, one instance lock. /health с last_success/error per component, version SHA, queue length, last heartbeat and model probe, stale cache timestamp. Автоматический deployment не запускает сам Mac, update вручную через проверенный commit/rollback. Runtime changelog и feature flags; не менять распаковщик. Не отправлять push автоматически после загрузки audit-only ZIP. Сборка/интеграции сначала в тестовой среде. Production approval только после блока 7.
