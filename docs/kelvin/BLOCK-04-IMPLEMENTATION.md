## ADR-11 — recommendations and decision continuity
`founder_jarvis/strategic_intelligence.py` deterministic analysis and recommendations: overdue Care; waiting booking cohort (>=5 records, >=3 pending and >=50%); month-specific group 3+ demand (>=5 Care records, >=3 matching groups and >=50% total); family content test (>=5 known groups, >=3 large groups and >=50% known); checkout diagnostic (>=10 checkout sessions, <50% both events). These are thresholds for an investigation/experiment, not causal inference or statistically significant trends. Each proposal ID, evidence numerator/denominator where applicable, action, KPI and method of checking. Priority: overdue, pending, month, family, checkout. No unobserved actions claimed. Zero denominator is unknown percentage. Prior-window zero is unknown percentage change, absolute difference preserved. Owner decision status suppresses a previously decided proposal from deterministic daily recommendation; no implicit adoption. If no new signal, do not invent one. Research fallback retains Block 03 behavior. Unresolved undecided signals may still reappear on different days.

`/strategy` shows current comparable metrics and proposals, `/decision ID accept|defer|reject` records explicit owner decision (no execution); `/decisions` reviews accepted proposals. Both owner channels use same shared job/lease and D1 typed decision memory. Record id derived from request ID; duplicate event is no-op, latest valid owner record per proposal wins. Stored baseline/KPI/date/action, not proof implementation. Rejection/defer may supersede prior acceptance even if signal no longer exists. After >=7d and nonoverlapping comparison window, show comparable current KPI if available, not attribution; point-in-time Care due check also delayed 7d. No autonomous KPI review for undetermined goals; owner can use existing memory correction/delete, deleting latest record may expose earlier still-active record. No automatic confirmation from ordinary free text. Natural owner chat receives verified computed data, explicit decision statuses and follow-up context for model reasoning; fixed `/strategy` and `/decisions` don't use model. No exact causal success claim or booking change. Actual model quality and ability to challenge wrong assumptions not measured yet.

`research_context` uses recent (<=7d) locally archived Block03 reports, validates quote against stored observation, host/topic, timestamp, URL and deduplicates; matches research topic to proposal ID as *context only*, not proof of business cause. Up to five source-linked excerpts; no new search calls for this fusion; full page verification and independent source review remain open. Owner prompt context includes structured analysis and research; model synthesis may still hallucinate, requires human eval. Do not describe the output as a verified external market fact. `autonomy.py` uses one new proposal in <=900-char briefing; decided recommendations omitted. Evening may point to ready review in archive only, no new notification channel. Block03 quiet hours, 08:00 one short message, no automatic TTS, background research and delivery dedup retained. No new background model calls for analytics. Explicit `/strategy` works from existing Business chat, no new Swift screen added; original animation unchanged.
